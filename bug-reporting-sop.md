# Bug Reporting Standard Operating Procedure (SOP)

## Purpose
To ensure all software bugs are reported clearly, consistently, and with enough detail for developers to reproduce and fix them.

## Scope
This SOP applies to all QA engineers and testers during the software testing process.

## Responsibilities
- QA Engineers: Identify and report bugs following this SOP.  
- Developers: Review and resolve reported bugs.  
- Team Leads: Verify severity and assign bugs appropriately.  

## Procedure
1. Reproduce the bug at least twice to confirm it is valid.  
2. Collect environment details: operating system, environment where it is occurring, browser, application version.  
3. Log into the bug tracking tool (e.g., JIRA, Bugzilla).  
4. Fill in required fields:  
   - Title: short description of the issue  
   - Steps to reproduce: numbered list of actions  
   - Expected result: what should happen  
   - Actual result: what actually happens  
   - Attachments: screenshots, logs, or videos  
   - Assign: assign it to the developer to fix further  
5. Mark the severity and priority:  
   - Severity: Critical / Major / Minor  
   - Priority: High / Medium / Low  
6. Submit the bug report and notify the team lead if urgent.
